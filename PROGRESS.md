- Weak heuristics never change priority; only Gmail Promotions/Social go to digest (and skip the LLM). The LLM may choose digest only for mail with bulk signals.
- Rule actions mark_read/star are stored as pending (need the modify scope, phases 3–4); category, tag and folder are applied.

- `notifications.message_id` is unique so a message can never notify twice.

## Known limitations (AI on folders)
- AI filing and AI sorting by instruction need a key; sorting by company needs the AI to have read the mail (it has, for new mail with a key). Sorting by sender works without AI.
- An AI task handles up to 300 mails per run (newest first); run it again for more. It stops at the daily token cap and says so.
- A subfolder is matched by name (ignoring case, or a near-identical company name); renaming a company subfolder makes the next mail create a new one with the AI's name.
- Sign-up has no email verification (there is no mail-sending service in the free setup); close it with REGISTRATION=closed on a server you don't want others to use.

## Known limitations (Phase 4)
- Writing is plain text (the HTML version is generated from it): no bold, lists or inline pictures. Forwards quote the original as text, so its formatting and inline pictures are not kept (its attachments are).
- Undo send and send later run on Sift's server: if the laptop is asleep or off at the time, the mail goes out when Sift is back (late, never lost; it stays a Gmail draft meanwhile).
- The drafts list asks Gmail for the 25 newest drafts per account, one request each (a few seconds with many drafts).
- Sender name and signature are Sift settings, not read from Gmail's "Send mail as" settings (that needs another scope).
- Follow-ups notice replies through Sift's own intake, so a reply to an account Sift no longer watches isn't seen.
- Phone: recipients are typed (comma-separated) with no address suggestions; the web suggests past senders.
- Sent mail shows in Gmail's Sent, not in Sift's feed.

## Known limitations (Phase 3c)
- Write access has to be granted in Google by the owner for each account (not done yet on the live accounts); until then actions show the permission dialog.
- Google may warn that the app is unverified when asking for gmail.modify (Testing mode; same as gmail.readonly). Add gmail.modify under the consent screen's Data access first (README §1).
- Actions work on whole conversations (as in Gmail); there is no per-message archive.
- Undo is on the web only (Z within 6 s); the phone has no undo button yet.
- Snooze presets use the device's clock and time zone; the server checks only that the time is in the future and within a year.
- Feed rows have no quick actions yet: open the mail, or use search's bulk actions.

## Known limitations (Phase 3b)
- Searches through Gmail take 4–6 s for 30 rows when many results are older mail Sift never stored (one header fetch each, 16 in parallel). Searches with Sift filters or on stored mail are faster (~2 s).
- Gmail doesn't give exact result counts, so Gmail searches page without a total.
- Sift filters (◆) only match mail Sift stored; older mail from before Sift is found by Gmail syntax only.
- By meaning covers mail delivered to the feed since Sift started plus a one-time pass over the last 90 days; silenced mail is never indexed (keyword search still finds it). The score cut-off (0.56, within 0.08 of the best) was tuned on 13 real mails and may need retuning as the index grows.
- Saved-search alerts check common Gmail syntax on the new mail itself; other operators ask Gmail, whose index can lag a just-arrived mail by a few seconds (such a match is then missed, never doubled).
- Search bulk actions are file and tag; mark read, archive and snooze arrive with 3c.

## Known limitations (Phase 3a)
- DNS rebinding between the image proxy's address check and its fetch is not closed (would need a resolver-pinned transport); the proxy still refuses private addresses at check time and on every redirect.
- Attachments are streamed whole through the server (fine for Gmail's 25 MB limit); no preview for PDFs or documents, only for raster images (PDF viewers can run scripts, so PDFs always download).
- The Android WebView sizes itself after load; very long mails scroll inside the page normally, but the height can jump once while images load.
- Message threads only show mail in the account the opened mail belongs to (Gmail threads are per account).
- "Load images" applies to the whole conversation, not "always for this sender" yet.

## Known limitations (Phase 2c)
- Grouping's optional AI layer (daily topic suggestions from subject lines) is not built; grouping uses rules only, as the brief allows.
- Group "mark all read" / "archive all" and the "in a group" search filter need the modify scope or Phase 3 search; smart folders need saved searches (Phase 3).
- Same-thread grouping only joins a thread to an existing group; the feed is still one row per mail, not per conversation (thread view is Phase 3).
- Group membership never reshuffles, so a mail assigned before a better partner arrived stays where it is (by design: stable groups).
- The web UI keeps its token in localStorage under a strict CSP; there is no "sign out everywhere" yet (JWTs expire after JWT_DAYS).
- Web drag-and-drop was checked with a simulated drop in the browser pane, not a real mouse drag; Android filing and the grouping prompt are built but not yet checked on the phone.
- The Docker image change (Node build stage, root build context) is written but not built here (no Docker on this machine).

## Known limitations (Phase 1)
- End to end ~23 s in push mode (~25 s poll): Gmail reports new mail ~17 s after its receive timestamp; processing with AI ~4 s. Not reducible on our side except by skipping the AI step.
- `sift.solarquack.in` is only reachable while the laptop is on with Sift and the tunnel service running.
- Docker Compose, Redis queue, Cloudflare Tunnel and push mode still not run.
- History older than ~a week expires: Sift restarts from "now" without a catch-up scan of the gap.
- When the daily token cap is hit, mail is delivered as normal right away; it is not queued for later AI processing.
- On LLM 429 one retry after 2 s, then normal/other; no longer backoff queue. No fallback provider yet (interface ready).
- No quiet hours, focus mode or per-category mute yet (brief §11; planned with Phase 2 notification settings).
- Mail detail shows plain text only (sandboxed HTML reader is Phase 3). No Room offline cache yet.
- (Rule editor, plain-English rules, onboarding scan, suggestions, opportunities, folders, grouping and the web UI were added in Phase 2.)
