## 0. What I found in the code (root causes)

| # | Symptom the owner sees | Cause in the code |
|---|---|---|
| F1 | **Android: an opened mail shows no contents until you collapse and expand it.** | `ThreadView.kt` → `MailWebView`: `loaded` is `remember(url)`, but the `WebViewClient` is created once and keeps the *first* state object. The screen first shows the saved conversation (old reader link), then the fresh one arrives with a **new** link (links are re-signed on every request). That creates a new `loaded = false`; the WebView loads the new link, but its "finished" callback sets the *old* state. The view stays transparent (alpha 0) for good. Collapse/expand rebuilds the WebView, so then it shows. |
| F2 | Opening mail is slow and "downloaded" mail still loads from the network. | Reader links (`/api/v1/render/{token}`) carry their expiry inside the token, so the same mail gets a different URL every time and no cache (WebView, service worker, phone storage) ever hits. Each open also makes the server fetch the mail from Gmail twice (conversation, then each message's page). Bodies are never downloaded ahead: the push prefetch saves only the conversation JSON, whose reader link expires after 6 h. |
| F3 | Android: blank feed on a slow connection. | Grouping is on for the owner, so the feed requests `/messages?grouped=true…`; the saved-copy lookup only tries `view=feed` URLs and never finds it. |
| F4 | Android: the push prefetch doesn't help the feed. | It saves `/messages?view=feed&limit=30`, a URL the feed never reads (saved copies are matched by exact URL). |
| F5 | Android: going back from a mail briefly shows an older list. | The quiet live reload updates the screen but not `FeedSessionCache`, which is what the feed shows first on return. |
| F6 | Web: blank page on a slow connection. | Saved copies (Cache Storage) are only used when the request **fails**. A slow request just waits. The feed also waits for `/grouping` before it asks for the right list (two round trips; the first answer is thrown away). |
| F7 | New mail doesn't always appear by itself on the phone. | The phone relies on silent FCM "sync" pushes (normal priority, so Android may delay them) and on reopening the app. Unlike the web, it has no live stream while it's open. |
| F8 | Refresh. | Pull-to-refresh only on Feed, Deals and To-do. The web has no refresh button. |
| F9 | OTP. | Nothing detects codes. (`rules.SECURITY_WORDS` only protects OTP mail from being silenced.) |
| F10 | Bulk. | No multi-select on Feed, Folder, Group or Silenced. Search has it, with only some actions. Nothing for timelines, to-dos or groups. Mail endpoints already accept up to 500 ids. |
| F11 | Ask Sift can't do everything. | The catalogue (49 actions) is missing VIP, mute thread, unsubscribe, unlabel, important, saved searches, quiet hours / muted categories, categories, templates, outbox/follow-ups, timeline section edit/delete, group merge / always-never group, folder notify/pin, and bulk to-dos/timelines. A step changes at most 200 conversations, and the docs say 6 steps where the code allows 8. |
| F12 | Small things | Android "📌 Pinned" chip only filters the rows already loaded (the web runs `is:pinned`). Android "Open in Gmail" opens Gmail's All Mail, not the mail. The phone has no Undo after archive/trash (known limitation). |

## 1. Mail opens at once, and contents are downloaded ahead (backend, Android, web)

**Backend**
- **Stable reader links.** Round the expiry up to a fixed window, so one mail keeps the same URL for hours. Reader pages get a long private cache time. A mail's content never changes, and the images/colours choice is already part of the URL.
- **One-request download.** `GET /messages/{id}/thread?bundle=1` returns the conversation with each message's finished, sanitized reader document inline, so the phone stores a whole mail in one request instead of 1 + N. There is a size cap per conversation; over it, the response falls back to links. The server still never stores bodies: they live only on the user's own device, like today's saved copies.
- **Prefetch guard.** Prefetch requests are rate-limited per user so they can't hammer Gmail's quota or the 1-OCPU server.

**Android**
- Fix F1. The loaded state belongs to the WebView itself, and the page isn't reloaded when only the link's signature changes.
- The body is shown from storage first (`loadDataWithBaseURL` with the saved document), then refreshed if needed. This is instant and works offline. The WebView's no-scripts, no-file-access settings stay as they are.
- **Background download.** After each feed load, and on every push, the newest N mails are saved (conversation + bodies) in the background, 2 at a time, skipping mails already saved. The storage cap is raised (see Q1/Q2).
- Fix F3, F4 and F5: one cache-key helper used by both the saving and the reading side; the grouped feed is covered; quiet reloads update the session cache.
- On a slow connection the saved list shows at once with a small "Updating…" line, never a blank screen.

**Web**
- **Real stale-while-revalidate.** Every page shows the browser's saved copy right away, then swaps in fresh data. The Offline bar appears only when the server really can't be reached.
- The feed remembers the grouping state, so its first request is the right one (fixes F6).
- In idle time, the newest N feed mails (conversation + reader pages) are downloaded into the service worker cache, 2 at a time. Opening one of them renders without the network.

## 2. Refresh and automatic new mail
- **Web:** a ↻ Refresh button in the page actions of every list page (Feed, Silenced, Folder, Group, Search, To-do, Timelines, Groups, Outbox, Senders, Attachments). It spins while loading. The live stream stays. New: if the stream is down, the page re-checks every 60 s while the tab is visible.
- **Android:** pull-to-refresh on every list screen (Folder, Group, Search, Silenced, Outbox, Senders, Attachments, Groups, Folders; Feed, Deals and To-do already have it). While the app is open, the phone listens to the same live stream as the web (`/api/v1/events`), so new mail shows within about a second without waiting for a silent push. The stream closes when the app goes to the background, so there's no battery cost. When you're scrolled down, the list doesn't jump; instead a "↑ N new mails" bar appears.

## 3. OTP codes
- **Backend** `app/otp.py`: a local detector, no AI (so it works with AI off). It looks for a 4–8 character code next to words like code, OTP, one-time, verification, passcode, PIN or "sign-in" in the subject, preview and body. It ignores amounts (₹/Rs/INR), dates, years, phone numbers and order/reference numbers. It runs in the pipeline on the body before redaction. **The code is never stored in the database or logs.** It only rides in that mail's notification payload, and the conversation API detects it live for the mail page. Tests use real-world shapes (Google, Microsoft, Amazon, Indian banks, Swiggy/Zomato, college portals) and false positives (debit alerts, invoices, tracking numbers).
- **Android notification:** the first button is **Copy code**. It copies the code, shows "Code copied" and clears the notification. The notification expires after 15 minutes (codes go stale). Lock-screen visibility follows Q3.
- **Mail page (web and phone):** a "Code 123456 · Copy" banner above the conversation. Web uses one click; the phone uses one tap with a haptic tick.

## 4. Select and act on many things at once
**One backend endpoint** `POST /api/v1/bulk`:
- **Targets:** `message_ids`, `group_ids` (expanded on the server to their mail), or `match` (the list's own filter, used for "select all N matching").
- **Action:** read, unread, archive, move to inbox, trash, spam, star, unstar, important, label / remove label, snooze, pin / unpin, file in folder, remove from this folder, add to group, remove from this group, tag, add to timeline, mute thread, make to-dos (AI; needs a key).
- **How it runs:** through the existing services, on whole conversations. Write access is checked first: one "Allow Sift to change mail?" dialog lists every account that needs it, and nothing changes until it's granted. Gmail changes go in batches (`messages.batchModify`, up to 1000 per call) with pacing. A large set runs as a job with progress.
- **Result:** counts plus an **Undo** for reversible actions. Trash is undone by restoring from Trash.

**UI**
- **Web:** a checkbox on every row (shown on hover, always shown once anything is selected) and Shift-click for a range. The header checkbox selects the page, then a "Select all N matching" link appears (Q6). A sticky action bar at the top shows "3 mails + 2 groups (41 mails)". Esc clears the selection.
- **Android:** long-press starts selecting (Q7), taps add or remove, a top bar shows the count and "Select all", and actions sit in a bottom bar with a More sheet. Back clears the selection.

**What is allowed when (Feed shows mail rows and group rows)**

| Selection | Allowed | Hidden |
|---|---|---|
| Only mails | Every mail action | — |
| Only groups | Each mail action applied to every mail in the selected groups, plus group actions: mute/unmute, merge (2+), rename (exactly 1), delete group (custom: the group goes, mail stays; automatic: "Ungroup") | Pin, add to timeline, reply/forward |
| Mails + groups | Mail actions on the mails plus every mail in the groups | Group-only actions |
| Anything that includes urgent mail inside a group | Allowed; the confirm dialog says "includes 2 urgent mails" | — |

Trash, spam, anything over 50 conversations, and anything that touches mail hidden inside groups asks first, with exact counts.

**Per page**
- **Folder view:** mail actions + "Remove from this folder" + "Move to folder…".
- **Folders tree:** select folders → move, merge into one, pin, notifications mode, delete (mail stays).
- **Group page:** mail actions + "Remove from group" + "Split into a new group".
- **Timelines:** select / select all → close, reopen, delete (mail stays), mark all their mail read, archive all their mail.
- **To-dos:** select / select all → done, not done, set due date, clear due date, delete.
- **Groups list:** select / select all → mute, unmute, delete (custom) / ungroup (automatic), merge, mark all read, archive all.
- **Search:** the same full action set (today it has only file/tag/read/archive/snooze).
- **Silenced:** mail actions + "Not like this" in bulk.

## 5. Ask Sift: everything the app can do, and bulk
- **New actions:** VIP add/remove, mute/unmute thread, unsubscribe, remove label, important / not important, move to inbox, not like this, ignore like this, merge groups, always/never group a sender, folder notifications and pin, saved searches (create, delete, pin, alert), categories, quiet hours and muted categories, reply templates, outbox (list, cancel a scheduled send, send now) and follow-ups, edit/delete timeline sections, close/reopen/delete **many** timelines, finish/delete/re-date **many** to-dos, list senders and attachments.
- **Bulk:** the per-step cap goes from 200 to Q10. Big steps run with live progress and use the same `/bulk` code as the UI, so behaviour is identical.
- **"These":** when Ask Sift is opened with things selected, the request can say "these" ("file these in Placements and mark them read"). The AI sees only the count, never the mail (Q11).
- **Unchanged:** one planner call per request, preview + Run, never sends mail, never permanently deletes.
- **Tests:** every new action; caps; AI off = zero calls; "these" can't reach another user's mail.
